# 行を緩めた配置配線（place_span_tbl.py）の説明

2026-10-05 作成。対象ツール: `src/place_span_tbl.py`（配置）、`src/check_span.py`（検算）、`run_span.sh`（一括実行）

---

## 0. 一言でいうと

これまでの配置配線（**段固定SAT**）は、各セルを置く「行」を回路から1つに決め打ちしていた。
このツールでは、その行を**少しだけ選べるようにする**。行を上にずらしたセルと子の間には「中継」を挟んで配線をつなぐ。
狙いは、段固定では置けなかった回路を、構造の空いている場所も使って置けるようにすることである。

---

## 1. 用語

| 用語 | 意味 |
|---|---|
| **SoPA** | 提案している配線構造。2入力の論理セル（PA）が行ごとに並び、ある行の PA は1つ上の行の PA の出力しか受け取れない |
| **行** | 構造の横一列。このツールでは **FF の側から数える**（行0 = FF がつながる行、行1 = その1つ上、…）。.v ファイルの「段」の番号とは逆向きなので注意（段 = 全行数 − 1 − 行） |
| **列** | 行の中の位置（0, 1, 2, …）。**列数** = その行に並ぶ PA の数 |
| **候補表** | 「ある行の列 k の PA は、1つ上の行のどの列から入力を選べるか」の表。構造を作るときの規則（`CAND_RULE`、今の規則=`now`、巡回=`cyclic_eq` など）で決まる |
| **セル** | 回路（ネットリスト）の論理素子1つ。PA に1つずつ置く |
| **親・子** | セル s の出力がセル u の入力につながるとき、s を親、u を子と呼ぶ |
| **h0** | そのセルから FF までの最長距離。段固定ではセルは必ず行 h0 に置かれる |
| **中継（FT, フィードスルー）** | 何も計算せず、入力をそのまま出力する PA。1行飛ばしたい配線の途中に置く。設定ビットは追加0 |
| **全部中継のネットリスト** | 段固定で全ての配線がちょうど1行差になるよう、あらかじめ中継セルを挟んだネットリスト（`results/eblif_relay/`）。このツールはこれを前提にする |
| **OPTIMAL / INFEASIBLE / UNKNOWN** | 置けた / 置けないと証明できた / 制限時間内に決着しなかった |

---

## 2. 背景：段固定の何が問題か

段固定では、セルの行は「FF までの最長距離」で決まる。（下の図はイメージで、実際の列数ではない）

```
行4  (入力側)   [ ][ ][ ][ ][ ][ ][ ][ ][ ][ ]   ← 構造には空きが多い
行3             [■][■][ ][ ][ ][ ][ ][ ][ ][ ]
行2             [■][■][■][■][■][ ][ ][ ]
行1             [■][■][■][■][■][■]               ← ほぼ満杯。ここで詰まる
行0  (FF側)     [■][■][■][■]
```

- 小さい回路を大きい構造（superset = 41回路全部が載るように作った1つの構造）に載せると、入力側の行はほとんど使われない。
- 一方で FF 側の行は満杯に近く、候補表の条件を全部は満たせずに **INFEASIBLE / UNKNOWN** になる回路がある（s125 構造・今の規則で9回路）。
- 先生の助言：「行を全部自由にすると計算が終わらない（全体SATは UNKNOWN だらけ）。だから、行の決まりを少しだけ緩めてはどうか」。

---

## 3. 4通りすべてに共通する決まり

| 決まり | 中身 |
|---|---|
| FF に直接つながるセル（h0 = 0） | 行0 に固定（段固定と同じ）。組合せ出力のセルも行0 |
| 親と子の行の差 | **1 か 2** に限る |
| 差が1 のとき | 段固定と同じ。子の列の候補表に、親の列が入っていればよい |
| 差が2 のとき | 間の行に**中継**を置く。「親 → 中継」と「中継 → 子」の2本とも候補表を満たす必要がある |
| 1マスに1つ | セルと中継は同じマスに重ねて置けない |
| 外部入力（PI）の枠 | 行が動くので、「各行で使う外部入力の種類数 ≤ その行の枠」をソルバの中で守る |
| FF の出力 | 構造上すべての行に届くので、制約にしない（段固定と同じ） |

```
差が1（中継なし）        差が2（中継あり）
  行3  親                  行4  親
   |                        |
  行2  子                  行3  中継   ← 素通しの PA を1つ使う
                            |
                           行2  子
```

---

## 4. 案B と 案A：セルが置ける行の範囲

### 案B「行の範囲を固定」（`MODE=B`）

各セルは **h0 か h0+1 のどちらか** に置ける。どのセルも最大1行しか上がらない。

### 案A「辺ごとに1行の余裕」（`MODE=A`）

親は **子の1つ上か2つ上** に置ける。子が上がれば親はさらに上がれるので、**ずれが入力側へ積み重なる**。

### 例：子 ← 親 ← 祖父 の鎖（h0 = 1, 2, 3）

```
          案B                         案A
子   (h0=1)  行1 か 行2              行1〜2
親   (h0=2)  行2 か 行3              行2〜4   （子が行2なら 行3か4）
祖父 (h0=3)  行3 か 行4              行3〜6   （親が行4なら 行5か6）
```

| | 案B | 案A |
|---|---|---|
| 置ける行 | h0, h0+1 の2択 | h0 〜「子の上限 + 2 の最小」（構造の一番上で打ち切り） |
| 1セルあたりの行の選択肢（bridge, 331セル） | 平均 1.98 行 | 平均 5.70 行 |
| 狙い | 「1行だけ緩める」と効くかを安く確かめる | 入力側の空いた行まで使う |
| 弱点 | 入力側の空きは使えない | 問題が大きく、時間とメモリが増える |

どちらも解く前に、親子で辻褄の合わない行（例：子のどの行から見ても、+1〜+2 の範囲に親の置ける行が無い）を削っておく。

---

## 5. 中継の置き方：子ごと と 共有

親 P の子 U1, U2 が、どちらも P の2行下にあるとき：

```
子ごと（FT=edge）              共有（FT=share）
      P                              P
     / \                             |
   F1   F2    ← 中継2つ              F       ← 中継1つ
    |    |                          / \
   U1   U2                        U1   U2
```

| | 子ごと（`FT=edge`） | 共有（`FT=share`） |
|---|---|---|
| 中継の数 | 2行差の配線1本につき1つ | 親1つにつき最大1つ |
| マスの消費 | 多い | 少ない |
| 候補表の条件 | F1 は U1 から、F2 は U2 から届けばよい（ゆるい） | 1つの F が U1 と U2 の**両方**から届く必要がある（きつい） |
| 有利そうな場面 | マスに余裕があり、候補表がきついとき | マスが足りないとき |

親の子どうしで混ぜてよい：1行下の子には親から直接、2行下の子には中継から、という形もとれる。

## 6. 4通りのまとめ

| 名前 | MODE | FT | 行の自由 | 中継 |
|---|---|---|---|---|
| 案B・子ごと | B | edge | 1行まで | 配線ごと |
| 案B・共有 | B | share | 1行まで | 親ごと |
| 案A・子ごと | A | edge | 積み重なる | 配線ごと |
| 案A・共有 | A | share | 積み重なる | 親ごと |
| （検算用）段固定 | fixed | — | なし | なし |

`MODE=fixed` は、行の選択肢が1つしかない特別な場合で、従来の `place_fixed_tbl.py` と同じ問題を解く（同じ答えが出ることを確認済み）。

## 7. ソルバ（CP-SAT）への書き方

| 部品 | 中身 |
|---|---|
| `x[セル, 行, 列]`（0/1） | そのセルをそのマスに置くなら 1。セルごとにちょうど1つが 1 |
| `g[配線]`（0/1） | その配線で中継を使うなら 1。行の関係「親の行 = 子の行 + 1 + g」 |
| `y[中継, 行, 列]`（0/1） | 中継の位置。使うときだけちょうど1つが 1 |
| 候補表 | 「子がマス(行h, 列k)にいる ⇒ 行h+1 の候補列のどれかに、親（g=0）か中継（g=1）がいる」という OR 条件 |
| 中継の入力 | 「中継がマス(行h, 列k)にいる ⇒ 行h+1 の候補列のどれかに親がいる」 |
| 重なり禁止 | マスごとに「1つまで」＋ 通し番号の「全部ちがう（AllDifferent）」 |
| 目的 | なし（置けるかどうかだけを判定）。そのため、解は中継を必要以上に使うことがある |

### なぜこの書き方にしたか（軽くするまでの経緯、girl10 = 48セル、s125 構造）

| 版 | やり方 | 案B | 案A | 問題 |
|---|---|---|---|---|
| 1 | 全マスの通し番号で表制約 | 24秒 / 1.0GB | 51秒 / 2.4GB | 重い |
| 2 | 行と列を別の変数にし、3〜4変数の表制約 | 19秒 / 1.3GB | 28秒 / 1.6GB | ソルバが表の1行ごとに 0/1 変数を作る（58,589個に膨張） |
| 3 | 0/1 変数＋OR 条件で直接書く | 4秒 / 0.2GB | 7秒 / 0.5GB | 「置けない」の証明が遅い（indep 自構造が 0秒 → 60秒で UNKNOWN） |
| **4（採用）** | 3 ＋ 通し番号の AllDifferent ＋ 前処理の probing を切る | **2秒** / 0.4GB | **15秒** / 1.6GB | — |

参考：段固定（従来ツール）は 1秒 / 0.14GB。

## 8. 使い方

### 1回路だけ

```bash
cd src
MODE=B FT=edge CAND_RULE=now ATIME=3600 \
  python3 place_span_tbl.py ../results/eblif_relay/girl10/mapped_girl10.v.eblif ../structures/superset_allrelay_s125.v
# → place_span_B_edge_girl10.json ができる（置けたとき）
python3 check_span.py ../results/eblif_relay/girl10/mapped_girl10.v.eblif ../structures/superset_allrelay_s125.v place_span_B_edge_girl10.json
```

| 環境変数 | 意味 | 既定 |
|---|---|---|
| `MODE` | `fixed` / `B` / `A` | `B` |
| `FT` | `edge`（子ごと）/ `share`（共有） | `edge` |
| `CAND_RULE` | 候補表の規則。**構造を作ったときと同じにする** | `now` |
| `ATIME` | 制限時間（秒） | 600 |
| `THREADS` | 並列スレッド数 | 8 |
| `PROBE` | 前処理の probing の強さ（0 で切る） | 0 |

### 回路 × 4通りをまとめて

```bash
nohup env JOBS=2 ATIME=3600 bash run_span.sh > span_run.log 2>&1 &
```

- 回路は `CKTS` の順に回る（既定：girl10 robm bridge proc81616 v16 pp proc1688 e15 e8 e2 e4 ＝ 小さい順）。
- 結果は `results/place_span_s125_now/<回路>_<MODE>_<FT>.log / .json`、表は `summary.txt`。
- メモリは1本 3〜5GB（bridge, 60秒時点）。`JOBS` は「空きメモリ(GB) ÷ 6」くらいにする。

### 検算（check_span.py）が確かめること

ソルバとは別に書いたプログラムで、次を確かめる。
1. 1マスに1つだけ置かれているか（セルと中継の両方）
2. 配線が、1行差なら候補表どおりか。2行差なら「親 → 中継 → 子」が候補表どおりか
3. FF に直接つながるセルが行0 にあるか
4. 外部入力の枠を超えていないか

## 10. 注意

- 全部中継のネットリストが前提。段固定で2行以上飛ぶ配線があると「対象外」と出て止まる。
- 解は中継の数を最小にしていない。中継の数で比べたいときは目的関数の追加が必要。
- `CAND_RULE` は構造を作ったときの規則と必ずそろえる（構造の .v には候補表そのものが書かれているが、このツールは規則から作り直している）。
